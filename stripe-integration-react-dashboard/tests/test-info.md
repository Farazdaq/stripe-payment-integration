# React Testing Strategy

This project follows the professional Testing Pyramid strategy using approximately 70% Unit Tests, 20% Integration Tests, and 10% End-to-End (E2E) Tests to balance speed, maintainability, and confidence. Unit tests are the largest portion because they are fast, isolated, and easy to maintain, and are mainly used to test React components, hooks, utility functions, stores, reducers, and service logic. Integration tests are used to verify multiple parts working together such as forms with validation, API interactions, authentication flows, routing behavior, and page-level features. E2E tests are reserved for critical business flows like login, checkout, onboarding, payments, and dashboard navigation using a real browser environment. The project uses Vitest as the primary test runner, React Testing Library for rendering and testing React components, `@testing-library/jest-dom` for enhanced DOM assertions, `@testing-library/user-event` for simulating realistic user interactions, JSDOM to provide a browser-like testing environment inside Node.js, Playwright for E2E browser automation, and MSW (Mock Service Worker) for API mocking and stable isolated testing. Unit and integration tests focus on correctness and feature reliability, while E2E tests ensure business-critical workflows behave correctly in production-like conditions. The recommended workflow is to maintain many small unit tests, fewer integration tests, and only a limited number of high-value E2E tests to keep the testing pipeline fast, scalable, and professional.
