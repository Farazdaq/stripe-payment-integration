# ESLint Rules (React + TypeScript)

| Rule                                               | What Is This Rule?                                    | Purpose                          | What It Prevents           | Example                             |
| -------------------------------------------------- | ----------------------------------------------------- | -------------------------------- | -------------------------- | ----------------------------------- | --- | -------- |
| `no-unused-vars`                                   | Checks for variables that are declared but never used | Keeps code clean                 | Dead code                  | `const name = "Ali"` never used     |
| `no-console`                                       | Detects console statements                            | Prevent debug logs in production | Console pollution          | `console.log(data)`                 |
| `eqeqeq`                                           | Enforces strict equality (`===`)                      | Avoid JS type coercion bugs      | Unexpected comparisons     | `5 == "5"`                          |
| `curly`                                            | Requires `{}` around blocks                           | Makes logic safer/readable       | One-line condition bugs    | `if(x) doSomething()`               |
| `semi`                                             | Requires semicolons                                   | Consistent syntax style          | Parsing inconsistencies    | Missing `;`                         |
| `quotes`                                           | Enforces quote style                                  | Consistent code formatting       | Mixed quotes               | `'hello'` vs `"hello"`              |
| `indent`                                           | Controls indentation spacing                          | Improves readability             | Messy formatting           | Wrong spacing                       |
| `camelcase`                                        | Enforces camelCase naming                             | Consistent naming convention     | Mixed naming styles        | `user_name`                         |
| `max-lines`                                        | Limits file line count                                | Keeps files maintainable         | Massive components/files   | 1000-line component                 |
| `max-lines-per-function`                           | Limits function size                                  | Encourages smaller functions     | God functions              | Huge handler logic                  |
| `max-depth`                                        | Limits nesting levels                                 | Improves readability             | Callback hell              | Deep nested `if`                    |
| `complexity`                                       | Measures branching complexity                         | Simplifies logic                 | Hard-to-maintain logic     | Too many conditions                 |
| `max-params`                                       | Limits function parameters                            | Cleaner APIs                     | Overloaded functions       | Function with 8 params              |
| `no-magic-numbers`                                 | Prevents unexplained numbers                          | Makes logic understandable       | Hidden business rules      | `if(age > 18)`                      |
| `prefer-const`                                     | Suggests `const` over `let`                           | Prevents accidental mutation     | Mutable variables          | `let name = "Ali"`                  |
| `no-var`                                           | Disallows `var`                                       | Uses modern JS standards         | Scope bugs                 | `var data = 5`                      |
| `object-shorthand`                                 | Simplifies object syntax                              | Cleaner objects                  | Verbose objects            | `{ name: name }`                    |
| `arrow-body-style`                                 | Simplifies arrow functions                            | Cleaner arrow syntax             | Unnecessary returns        | `{ return value }`                  |
| `prefer-template`                                  | Encourages template literals                          | Cleaner string building          | String concatenation mess  | `"Hi " + name`                      |
| `no-duplicate-imports`                             | Prevents repeated imports                             | Cleaner imports                  | Duplicate modules          | Multiple imports same file          |
| `sort-imports`                                     | Organizes imports alphabetically                      | Better structure                 | Import chaos               | Random import order                 |
| `import/order`                                     | Groups imports logically                              | Cleaner architecture             | Mixed import groups        | External/internal mixed             |
| `consistent-return`                                | Requires consistent return behavior                   | Predictable functions            | Undefined return bugs      | Missing return                      |
| `default-case`                                     | Requires default in switch                            | Handles unknown cases            | Unhandled states           | Missing fallback                    |
| `no-fallthrough`                                   | Prevents switch fallthrough                           | Avoids accidental execution      | Logic bugs                 | Missing `break`                     |
| `no-shadow`                                        | Prevents variable shadowing                           | Avoids scope confusion           | Hidden variable overwrite  | Nested `user` variable              |
| `no-use-before-define`                             | Prevents using before declaration                     | Safer execution order            | Hoisting confusion         | Calling before define               |
| `no-undef`                                         | Detects undefined variables                           | Prevents runtime crashes         | Typo variables             | `userNmae` typo                     |
| `react/jsx-key`                                    | Requires `key` in React lists                         | Helps React track items          | Rendering issues           | `.map()` without `key`              |
| `react/self-closing-comp`                          | Enforces self-closing JSX                             | Cleaner JSX                      | Verbose components         | `<Comp></Comp>`                     |
| `react/no-array-index-key`                         | Prevents array index as key                           | Stable rendering                 | UI re-render bugs          | `key={index}`                       |
| `react-hooks/rules-of-hooks`                       | Enforces proper hook usage                            | Keeps React lifecycle stable     | Broken hooks               | Hook inside `if`                    |
| `react-hooks/exhaustive-deps`                      | Checks `useEffect` dependencies                       | Prevent stale state              | Missing dependencies       | Missing dep in effect               |
| `react-refresh/only-export-components`             | Restricts exports for Fast Refresh                    | Stable hot reload                | Refresh failures           | Exporting helpers in component file |
| `@typescript-eslint/no-explicit-any`               | Disallows `any` type                                  | Keeps TS strict                  | Loss of type safety        | `const data: any`                   |
| `@typescript-eslint/consistent-type-imports`       | Enforces `import type`                                | Optimizes TS builds              | Mixed type/runtime imports | `import { Type }`                   |
| `@typescript-eslint/no-unused-vars`                | TS-aware unused variable detection                    | Cleans TS code                   | Dead TS variables          | Unused typed vars                   |
| `@typescript-eslint/explicit-function-return-type` | Requires return types                                 | Clear APIs                       | Ambiguous returns          | Missing return type                 |
| `@typescript-eslint/strict-boolean-expressions`    | Makes conditions strict                               | Safer logic checks               | Truthy/falsy bugs          | `if(value)`                         |
| `@typescript-eslint/no-floating-promises`          | Detects unhandled promises                            | Safer async code                 | Silent async failures      | Missing `await`                     |
| `@typescript-eslint/no-misused-promises`           | Prevents incorrect async usage                        | Reliable async behavior          | Async misuse               | Async event handler mistakes        |
| `@typescript-eslint/consistent-type-definitions`   | Enforces consistent `type/interface` style            | Cleaner TS architecture          | Mixed type styles          | Random interface/type usage         |
| `@typescript-eslint/array-type`                    | Standardizes array typing                             | Consistent TS syntax             | Mixed array styles         | `Array<string>`                     |
| `@typescript-eslint/no-inferrable-types`           | Prevents redundant typing                             | Cleaner TS code                  | Verbose typing             | `const age: number = 5`             |
| `@typescript-eslint/prefer-nullish-coalescing`     | Encourages `??` operator                              | Safer fallback logic             | Falsy value bugs           | `value                              |     | default` |
| `@typescript-eslint/prefer-optional-chain`         | Encourages optional chaining                          | Cleaner null checks              | Nested checks              | `obj && obj.a`                      |
| `accessor-pairs`                                   | Requires getter/setter pairs                          | Consistent object APIs           | Incomplete accessors       | Getter without setter               |
| `array-callback-return`                            | Ensures array callbacks return values                 | Correct array operations         | Broken `.map()`            | Missing return in map               |
| `dot-notation`                                     | Encourages dot property access                        | Cleaner syntax                   | Verbose property access    | `obj["name"]`                       |
| `guard-for-in`                                     | Protects `for-in` loops                               | Safe object iteration            | Prototype pollution        | Unsafe object loops                 |
| `new-cap`                                          | Enforces constructor capitalization                   | Clear constructor usage          | Misleading functions       | `person()` vs `Person()`            |
| `no-alert`                                         | Prevents browser alerts                               | Better UX practices              | Annoying popups            | `alert("Hello")`                    |
| `no-empty-function`                                | Prevents empty functions                              | Avoids placeholder code          | Forgotten implementations  | Empty handler                       |
| `no-eval`                                          | Disallows `eval()`                                    | Improves security                | Code injection risks       | `eval(code)`                        |
| `no-implied-eval`                                  | Prevents indirect eval usage                          | Safer execution                  | Hidden eval security risks | `setTimeout("code")`                |
| `no-loop-func`                                     | Prevents functions inside loops                       | Avoids closure issues            | Loop bugs                  | Function inside `for`               |
| `no-new`                                           | Prevents unused constructors                          | Avoids wasted objects            | Unused instances           | `new Date()`                        |
| `no-return-await`                                  | Removes redundant await                               | Cleaner async code               | Unnecessary async layers   | `return await data`                 |
| `no-throw-literal`                                 | Requires throwing Error objects                       | Better debugging                 | Weak error handling        | `throw "error"`                     |
| `no-unneeded-ternary`                              | Simplifies ternary expressions                        | Cleaner logic                    | Verbose conditions         | `x ? true : false`                  |
| `prefer-arrow-callback`                            | Encourages arrow callbacks                            | Cleaner callbacks                | `this` confusion           | Old callback functions              |
| `prefer-destructuring`                             | Encourages destructuring                              | Cleaner variable access          | Repetitive property access | `user.name` repeatedly              |
| `require-await`                                    | Ensures async functions use await                     | Prevents fake async              | Misleading async code      | `async` without `await`             |
